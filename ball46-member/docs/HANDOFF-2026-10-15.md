## Current user-approved UI design
1. Expanded featured match summary stays compact. LIVE MATCH STATISTICS on the left and SIGNAL ENTRY HISTORY on the right; Event Flow follows full-width, then MATCH FACTS six cards in one row on desktop (tablet 3 cols, phone 2).
2. Statistics must not stretch vertically when many signals exist; each column should size to content. A former bug in MATCH FACTS was three grid-template-rows for six columns: fixed by overriding rows to auto.
3. SIGNAL ENTRY HISTORY is an Emerald Premium panel; **NO BORDER around its outer/main panel** as of latest deployed source.
4. Each individual Signal is a separate, rounded, Emerald card with **NO BORDER** either. Selected signal indicated by subtly lighter green fill (no selected border). Approximately 5px spacing between cards.
5. Each card's content must be in **ONE HORIZONTAL TEXT LINE** left to right, not vertically stacked field labels/values. Current V7 implementation uses spans in `featured-history-compact-row` with inline flex, small typography ~9–11px, min-height 23px + card vertical padding 5px. On narrow viewports allow horizontal scroll rather than distort. Do not regress to multi-row grid.
6. Card content: minute, market/period, selection + line, odds, bookmaker, entry score, corner score if applicable, official result, real P/L in Units only when settled and supplied. Do NOT compute outcome from live score; do NOT invent missing PENDING; use NO DATA if no valid result. Display engine values WIN, LOSS, PUSH (also HALF_WIN/HALF_LOSS, VOID, LIVE, UNRESOLVED as supplied).
7. Cards are READ-ONLY: clicking individual Signal cards MUST NOT navigate or switch active signal. `Technical Details` inside Corners card can expand locally to show full original Engine rule and odds provenance, without navigation. Keep all original data untouched.
8. Colors: Emerald, clean premium typography, no unnecessary gradients/borders. Do not change other widgets without explicit instruction.
9. Footnote: earlier versions accidentally rendered tall cards due to multiple subcolumns and Corners details. The user repeatedly corrected: one line per card, cards separate, no outer/inner borders.
10. Asset cache busting for HTML currently includes `featured=20261015-borderless-panel-v9`.
