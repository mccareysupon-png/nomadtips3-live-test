ENGINE TRUTH

Active Settings

ส่วนนี้ใช้ดูว่า engine กำลังใช้ Settings ชุดใดอยู่จริง ไม่ใช่ค่าที่กำลังพิมพ์ในฟอร์มก่อนกด Save

Active Version

หมายเลขเวอร์ชันของชุด Settings ที่ใช้งานอยู่ เมื่อบันทึกค่าใหม่ระบบจะสร้างเวอร์ชันใหม่ ทำให้รู้ว่า signal แต่ละตัวเกิดจากกติกาชุดไหน

Last Updated

เวลาที่ Settings เวอร์ชันนั้นถูกบันทึก ใช้เช็กว่าค่าที่ Active เป็นค่าที่แก้เมื่อไร

Applies From Cycle

รอบ engine ที่ Settings เวอร์ชันนั้นเริ่มมีผล การ Save จะไม่เปลี่ยนกติกากลางรอบ แต่จะมีผลตั้งแต่ cycle ถัดไป

สิ่งสำคัญ: เมื่อเกิด SIGNAL ใหม่ ระบบเก็บ snapshot ของ Settings ที่ Active ณ เวลานั้นไว้กับ SIGNAL ดังนั้นเปลี่ยน Settings วันหลัง ประวัติ SIGNAL เดิมจะไม่ถูกเขียนทับ

A · DETECTION WINDOW

Time and score gate

ด่านแรกใช้กำหนดช่วงเวลาที่อนุญาตให้หา SIGNAL และเงื่อนไขเรื่องผลต่างสกอร์

1. Minute From

Default 550–120 นาที

นาทีแรกที่อนุญาตให้เกมผ่านด่านเวลา หากนาทีปัจจุบันต่ำกว่าค่านี้ engine จะยังเฝ้าดู แต่ยังไม่ถือว่าผ่าน Detection Window

ตั้งต่ำลงเริ่มหาเร็วขึ้น เกมเข้ากระบวนการมากขึ้น
ตั้งสูงขึ้นรอให้เกมพัฒนาไปมากขึ้นก่อน
ตัวอย่างตั้ง 55 → นาที 54 ไม่ผ่าน แต่นาที 55 เริ่มมีสิทธิ์ผ่าน

2. Minute To

Default 880–120 นาที

นาทีสุดท้ายที่ยังยอมให้เกมผ่านด่านเวลา ค่า Minute From ต้องไม่มากกว่า Minute To

ตั้งต่ำลงตัดช่วงท้ายเกมออกเร็วขึ้น
ตั้งสูงขึ้นเปิดโอกาสให้เกมช่วงท้ายมากขึ้น
ตัวอย่างตั้ง 88 → นาที 88 ยังผ่านได้ แต่นาที 89 ไม่ผ่าน

3. Rolling Window Minutes

Default 51–15 นาที

จำนวน “นาทีล่าสุด” ที่ใช้วัดโมเมนตัม แล้วนำไปเทียบกับหน้าต่างก่อนหน้าที่มีขนาดเท่ากัน ระบบจึงดูการเปลี่ยนแปลง ไม่ใช่ดูยอดสถิติทั้งเกมอย่างเดียว

ตัวอย่าง Window 5: ช่วง 65–70 นาที เทียบกับช่วง 60–65 นาที

ตั้งสั้นตอบสนองไว เห็นแรงเร่งเร็ว แต่แกว่งง่าย
ตั้งยาวนิ่งขึ้น แต่ตอบสนองต่อการเปลี่ยนเกมช้ากว่า
หลักอ่านLatest N minutes เทียบ Immediately Previous N minutes

4. Score Difference Filter

Default OFF

สวิตช์เปิด/ปิดด่านผลต่างประตู ถ้า OFF ระบบไม่ใช้ผลต่างสกอร์เป็นตัวตัด ถ้า ON จะใช้ค่า Max Score Difference ด้านล่าง

OFFไม่สนว่าคะแนนห่างกี่ลูก
ONต้องผ่านเพดานผลต่างสกอร์
ข้อควรจำMax Score Difference มีผลจริงเมื่อ Filter = ON

5. Max Score Difference

Default 10–20 ลูก

ผลต่างประตูสูงสุดที่ยอมรับเมื่อ Score Difference Filter เปิด ระบบใช้ค่าผลต่างแบบค่าสัมบูรณ์ จึงใช้ทั้งกรณี HOME นำหรือ HOME ตาม

ตัวอย่าง: ตั้ง 1 → 1-0, 0-1, 2-1 ผ่าน; 2-0 หรือ 0-2 ไม่ผ่าน

B · HOME EVIDENCE

Pressure, hunger and new events

ส่วนนี้เป็นหัวใจของการดูว่า HOME กำลังเร่งเกมจริงหรือไม่ โดยใช้แรงกดดัน การเปลี่ยน trend และ event ใหม่

1. Attack Weight

Default 10–10

น้ำหนักของค่า Attack ในสูตร Pressure ยิ่งมาก Attack ปกติยิ่งมีอิทธิพลต่อคะแนนแรงกดดันมากขึ้น

Pressure = Attack Weight × Attack Delta + Dangerous Attack Weight × Dangerous Attack Delta

เพิ่มให้ความสำคัญกับ Attack ปกติมากขึ้น
ลดลดบทบาท Attack ปกติ
ข้อจำกัดAttack Weight และ Dangerous Attack Weight ห้ามเป็น 0 พร้อมกัน

2. Dangerous Attack Weight

Default 20–10

น้ำหนักของ Dangerous Attack ในสูตร Pressure ค่า default สูงกว่า Attack ปกติ ทำให้การบุกอันตรายมีผลต่อแรงกดดันมากกว่า

เพิ่มระบบไวต่อ Dangerous Attack มากขึ้น
ลดลดอิทธิพลของ Dangerous Attack
ตัวอย่างWeight 2 → Dangerous Attack เพิ่ม 3 ครั้ง มีน้ำหนัก 6 คะแนน

3. HOME Pressure Share %

Default 54%0–100%

สัดส่วนแรงกดดันของ HOME เทียบกับแรงกดดันรวมใน rolling window ล่าสุด

HOME Pressure Share = HOME Pressure ÷ (HOME Pressure + AWAY Pressure) × 100

ตั้งสูงคัดเข้ม ต้องเป็นฝ่ายกดเกมชัดเจน
ตั้งต่ำผ่านง่ายขึ้น แม้เกมสูสีกว่า
ตัวอย่างตั้ง 60% → HOME ต้องมี Pressure Share อย่างน้อย 60%

4. Trend Conditions Required

Default 2 / 31/3 · 2/3 · 3/3

กำหนดว่าจาก 3 Trend Conditions ต้องผ่านอย่างน้อยกี่ข้อ ได้แก่ Home Pressure Trend, Home Pressure Share และ Match Tempo Trend

1 / 3ผ่อนที่สุด ผ่านเพียงหนึ่งเงื่อนไขก็พอ
2 / 3สมดุล ต้องเห็นภาพกดเกมมากกว่าหนึ่งมิติ
3 / 3เข้มที่สุด ต้องผ่านทุก trend

5. New HOME Event Gate

Default ON

กำหนดว่าต้องมี event ใหม่ของ HOME ใน rolling window ล่าสุดหรือไม่ โดย event มาจาก SOT, Shot Off และ Corner ที่เปิดใช้งาน

ONต้องมี event ใหม่ตาม Evidence rule
OFFbypass ด่าน event ใหม่ แม้ค่า SOT / Shot Off / Corner จะยังถูกเก็บไว้
ผลOFF ทำให้เกมผ่านง่ายขึ้นเพราะไม่บังคับ fresh event

6. SOT enabled

Default ON

เปิดให้ Shots On Target เป็นหนึ่งใน evidence ที่ใช้ตรวจเหตุการณ์ใหม่ของ HOME

7. SOT Delta Minimum

Default 11–20

จำนวน SOT ใหม่ขั้นต่ำของ HOME ใน rolling window ล่าสุดที่ถือว่า evidence ตัวนี้ผ่าน

ตัวอย่าง: ตั้ง 1 → ช่วงล่าสุดมี SOT เพิ่มจาก 2 เป็น 3 ถือว่า Delta = 1 และผ่าน

8. Shot Off enabled

Default ON

เปิดให้การยิงไม่ตรงกรอบของ HOME เป็นหนึ่งใน evidence ที่ใช้ตรวจ event ใหม่

9. Shot Off Delta Minimum

Default 11–20

จำนวน Shot Off ใหม่ขั้นต่ำใน rolling window ล่าสุดที่ต้องเกิดจึงถือว่า evidence ตัวนี้ผ่าน

10. Corner enabled

Default ON

เปิดให้ Corner ของ HOME เป็นหนึ่งใน evidence ที่ใช้ตรวจ event ใหม่

11. Corner Delta Minimum

Default 11–20

จำนวน Corner ใหม่ขั้นต่ำใน rolling window ล่าสุดที่ถือว่า evidence ตัวนี้ผ่าน

12. Evidence Required

Default ANYANY / ALL

กำหนดความสัมพันธ์ของ evidence ที่ “เปิดใช้งาน” อยู่

ANYมีอย่างน้อยหนึ่ง evidence ผ่านก็พอ
ALLevidence ทุกตัวที่เปิดต้องผ่านพร้อมกัน
กรณี Event Gate OFFด่านนี้ถูก bypass เพราะไม่บังคับ event ใหม่
ตัวอย่าง: เปิด SOT + Shot Off + Corner และเลือก ANY → มี Corner ใหม่อย่างเดียวก็ผ่าน evidence ได้ หากถึง minimum ที่ตั้งไว้

C · HOME ASIAN HANDICAP

Live market and price gate

หลัง Detection และ Evidence ผ่าน ระบบจึงตรวจตลาด Asian Handicap, line, odds และความสดของราคา

MarketFull Match Live AH
SideHOME
Bookmakerตามที่แสดงในหน้า Settings

1. Allowed Lines

Default ANYANY / SELECTED

กำหนดว่าจะยอมรับ HOME Asian Handicap line แบบใด

ANYยอมรับ AH line ที่ valid ทุก line
SELECTEDยอมรับเฉพาะ line ที่เลือกไว้ในช่อง Selected HOME Lines
ผลSELECTED ช่วยจำกัดช่วงต่อรองให้ตรงกลยุทธ์มากขึ้น

2. Selected HOME Lines

หน้า Settings เลือก +5 ถึง -5 ทีละ 0.25

รายการ HOME AH line ที่อนุญาตเมื่อ Allowed Lines = SELECTED สามารถเลือกหลายค่าได้ เช่น 0, -0.25, -0.5 หรือช่วงอื่นตามต้องการ

ตัวอย่าง: เลือก 0, -0.25, -0.50 → ถ้าราคาปัจจุบัน HOME อยู่ -0.75 จะไม่ผ่าน AH line gate

3. Minimum Odds

Default 1.501.01–6.00

ราคาขั้นต่ำของ HOME ที่ยอมรับ ถ้า HOME odds ต่ำกว่าค่านี้จะไม่ผ่านราคา

ตั้งสูงคัดราคาต่ำออกมากขึ้น
ตั้งต่ำยอมรับราคากว้างขึ้น
ตัวอย่างตั้ง 1.70 → ราคา 1.69 ไม่ผ่าน; 1.70 ขึ้นไปผ่านด้าน minimum

4. Maximum enabled

Default OFF

สวิตช์เปิดเพดาน Odds สูงสุด ถ้า OFF จะตรวจเพียง Minimum Odds; ถ้า ON จะใช้ Maximum Odds ด้านล่างร่วมด้วย

5. Maximum Odds

1.01–6.00 เมื่อเปิดใช้งาน

ราคาสูงสุดที่ยอมรับเมื่อ Maximum enabled = ON และค่า Minimum Odds ต้องไม่สูงกว่า Maximum Odds

ตัวอย่าง: Minimum 1.70 + Maximum 2.50 → HOME odds ต้องอยู่ระหว่าง 1.70 ถึง 2.50

6. Maximum Price Age (seconds)

Default 90s1–3600 วินาที

อายุสูงสุดของ “ราคาล่าสุด” ที่ระบบยอมรับ วัดจากเวลาที่ source อัปเดตราคาจนถึงเวลาที่ engine ตรวจ ถ้าเกินค่านี้ถือว่าราคาเก่าเกินไปและไม่ใช้ล็อก SIGNAL

ตั้งต่ำบังคับราคาสดมากขึ้น แต่ถ้า source มาช้าก็อาจตกหล่นง่ายขึ้น
ตั้งสูงยอมรับราคาที่เก่ากว่าได้ แต่เสี่ยงใช้ราคาไม่ทันสถานการณ์มากขึ้น
ค่าปัจจุบันที่เหมาะ90 วินาที = 1 นาที 30 วินาที เป็นจุดสมดุลที่ดี
ตัวอย่าง: ราคาอัปเดต 12:00:00 ตรวจ 12:01:10 → อายุ 70s ผ่าน; ตรวจ 12:01:40 → อายุ 100s เกิน 90s จึงเป็น STALE

7. One Signal Per Match

Default ON

ควบคุมว่าคู่เดียวกันสามารถล็อก SIGNAL ได้กี่ครั้ง

ONคู่หนึ่งล็อกได้ครั้งเดียว
OFFคู่เดิมสามารถล็อก SIGNAL ใหม่ได้อีก หากกลับมาผ่านเงื่อนไข
ข้อสังเกตON ช่วยกัน signal ซ้ำในแมตช์เดียวกัน

SETTINGS ACTIONS

ปุ่มด้านล่างหน้า Settings

ค่าต่าง ๆ จะยังไม่เปลี่ยน engine จนกว่าจะสั่ง Save ตามขั้นตอนของระบบ

SAVE & APPLY NEXT CYCLE

ตรวจความถูกต้องของ Settings ทั้งชุด หากมีค่าใดไม่ผ่าน validation จะไม่บันทึกทั้งชุด หากผ่านจะ staging เป็นเวอร์ชันใหม่และเริ่มใช้ cycle ถัดไป

RELOAD ACTIVE

โหลด Settings ที่ Active อยู่จริงกลับมาใส่ฟอร์ม เหมาะเมื่อแก้ค่าในหน้าจอไปแล้วแต่ยังไม่ต้องการ Save

RESTORE DEFAULT

นำค่า default ของระบบกลับมาเป็นชุดที่จะ Apply ตามกลไกการบันทึกของ Settings

หลักการจำง่าย: Save = เปลี่ยนอนาคตตั้งแต่ cycle ถัดไป ไม่ย้อนแก้ SIGNAL หรือ Settlement ที่เกิดไปแล้ว
